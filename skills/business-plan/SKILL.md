# 📝 사업계획서 작성

사업단(LINC 3.0, RIS, BK21, 글로컬대학 등)이나 기관이 주관기관에 낼 연차 사업계획서 초안을 만들어 드립니다. 근거 자료 조사부터 계획서 본문, 예산표, 규정 점검, 사업단장에게 올릴 1페이지 요약까지 한 번에 이어집니다. 계획서를 처음 써 보는 사업단 직원도 공고문과 예산 규모만 알려 주면 시작할 수 있습니다.

## 시작할 때 물어볼 것
최대 3개. 사용자가 이미 말했으면 묻지 않는다. 답이 없으면 괄호 안 기본값으로 진행한다.
1. 어떤 사업이고 몇 차년도 계획인가요? 공고문·사업 안내서·전년도 계획서가 있으면 붙여 주세요. (기본값: 사용자가 말한 사업명만으로 진행하고, 공고 요건은 "[공고 확인 필요]"로 표시)
2. 당해연도 사업비 규모와 세목 구조는 어떻게 되나요? (기본값: 국가연구개발사업 기본 세목인 인건비·연구시설장비비·연구활동비·연구수당·간접비로 편성)
3. 계획서를 받는 사람은 누구인가요? 주관기관 제출용인지, 내부 검토용인지 알려 주세요. (기본값: 주관기관 제출용 초안 + 사업단장 내부 보고용 요약)

각 단계가 끝나면 "여기까지 확인하시겠어요, 계속 진행할까요?"를 한 번만 묻고, 사용자가 "끝까지 진행"이라고 하면 다시 묻지 않는다.

## 진행 단계

### 1단계. 동향·근거 조사 — 전문가: `trend-researcher`(연구·산업 동향 조사원)
- **위임**: `trend-researcher` 서브에이전트가 설치되어 있으면 그에게 맡긴다. 없으면 아래 요령으로 직접 한다.
- **요령**:
  - 출처 없는 동향은 동향이 아니다. 모든 주장에 확인 가능한 출처를 붙인다.
  - 신호 강도를 약함(단일 출처)·보통(복수 독립 출처)·강함(정책·투자·통계에서 일관 확인)으로 구분한다.
  - 정책은 언론 요약이 아니라 보도자료·고시·법령 원문을 확인하고, 시행 시기와 적용 대상을 정확히 옮긴다.
  - 확인되지 않은 수치·기관명·정책명은 쓰지 않고 "확인 필요"로 표시한다.
  - 흥미로운 사실 나열이 아니라, 이 동향이 우리 사업에 어떤 선택지를 주는지로 끝맺는다.
- **이 단계 산출물**: 동향 브리프(핵심 요약 3줄 → 주요 동향 → 정책·제도 변화 → 우리에게 주는 함의 → 불확실성 → 출처 목록)

  | 동향 | 분야 | 신호 강도 | 근거 출처 수 | 예상 영향 | 확신도 |
  |---|---|---|---|---|---|
- **다음 단계로 넘길 것**: 계획서 "필요성과 배경"에 넣을 통계·정책 근거 목록(출처 포함), 공고 우선순위와 맞닿는 동향

### 2단계. 계획서 초안 — 전문가: `proposal-writer`(연구과제·사업 제안서 작성가)
- **위임**: `proposal-writer` 서브에이전트가 설치되어 있으면 그에게 맡긴다. 없으면 아래 요령으로 직접 한다.
- **요령**:
  - 공고문과 평가지표를 끝까지 읽은 뒤에 쓴다. 분량·서식·필수 첨부·지원 자격 중 하나만 어겨도 탈락한다.
  - 우리가 하고 싶은 것이 아니라 공고를 낸 부처·기관이 해결하려는 문제에서 출발하고, 공고의 용어로 틀을 짠다.
  - 평가지표 배점에 비례해 분량과 서술 순서를 배분한다.
  - 기관·연구진의 역량을 허위로 기재하지 않는다. 모든 주장은 확인 가능해야 한다.
  - 요약(1쪽)은 가장 마지막에 쓴다. "후속 과제 지원 예정"만으로 지속가능성을 채우지 않는다.
- **이 단계 산출물**: 계획서 논리 구조에 따른 초안 — 1.요약 → 2.필요성과 배경 → 3.목표와 내용(연차별 목표, 추진 체계, 투입→활동→산출→성과 논리 모형) → 4.수행 역량 → 5.성과지표와 평가 계획(지표별 목표치·측정 방법·시점) → 6.성과 활용·확산 → 7.예산(3단계에서 채움). 함께 평가지표 대응표를 붙인다.

  | 평가지표(배점) | 공고가 묻는 것 | 계획서 해당 절 | 우리의 핵심 근거 | 예상 지적·보완 |
  |---|---|---|---|---|
- **다음 단계로 넘길 것**: 본문에 등장하는 활동·인력·장비 목록(예산 항목의 원천), 성과지표 목록

### 3단계. 세목별 예산표 — 전문가: `budget-manager`(예산·집행 관리자)
- **위임**: `budget-manager` 서브에이전트가 설치되어 있으면 그에게 맡긴다. 없으면 아래 요령으로 직접 한다.
- **요령**:
  - 계획서 본문의 활동 목록에서 예산 항목을 도출한다. 본문을 쓴 뒤 예산을 끼워 맞추지 않는다.
  - 모든 항목에 산출식(수량 × 단가 × 기간)과 근거 문장을 붙인다.
  - 세목 명칭·편성 비율·간접비율은 해당 사업 협약과 관리 지침을 따른다. 확실치 않으면 지어내지 않고 "지침 확인 필요"로 표시한다.
  - 인건비는 참여율·참여 기간과 일치해야 하고, 간접비는 기관 고시 비율과 공고 상한을 함께 확인한다.
  - 사용 불가 항목(사적 경비, 사업과 무관한 장비)을 넣지 않는다.
- **이 단계 산출물**: 세목별 예산 편성·집행 계획표(단위: 천 원)

  | 세목 | 세부 항목 | 편성액 | 1분기 | 2분기 | 3분기 | 4분기 | 산출 근거 | 비고 |
  |---|---|---|---|---|---|---|---|---|
  | 인건비 | 참여연구원·학생인건비 | | | | | | 참여율 ○% × 월 ○원 × ○개월 | 참여율 확인 |
  | 연구활동비 | 재료·출장·회의·전문가 활용 | | | | | | | |
  | 간접비 | 기관 간접비 | | | | | | 직접비 × 기관 고시율 ○% | 공고 상한 확인 |
  | 합계 | | | | | | | | |
- **다음 단계로 넘길 것**: 예산표와 본문 활동의 1:1 대응 여부, 인건비·장비·회의비 등 규정 점검이 필요한 항목

### 4단계. 규정 점검 — 전문가: `compliance-checker`(규정·법령 검토관)
- **위임**: `compliance-checker` 서브에이전트가 설치되어 있으면 그에게 맡긴다. 없으면 아래 요령으로 직접 한다.
- **요령**:
  - 이 점검은 법률 자문이 아니다. 최종 판단은 법무·감사 부서와 확인하도록 안내한다.
  - 모든 결론에 근거 법령명(또는 규정명)과 판단 이유를 남긴다.
  - 조항 번호·과태료 액수·처벌 수위를 확실히 모르면 적지 않는다. "개인정보보호법상 확인 필요"처럼 법령명 수준으로 표시한다.
  - 계획서에 해당하는 영역만 본다. 주로 사업비 관리 지침(세목·간접비·인건비), 개인정보(참여자 명단·설문), 계약(장비 구매·용역), 연구윤리(국가연구개발혁신법)이다.
  - 사용자가 준 자료 밖의 사실을 가정하지 않는다.
- **이 단계 산출물**: 규정·법령 준수 검토 보고서(종합 판단: 적정 / 조건부 적정 / 보완 필요 / 법무 확인 필요)

  | 항목 | 현황 | 적용 법령·규정 | 위험(높음/보통/낮음) | 필요 조치 | 담당 | 기한 |
  |---|---|---|---|---|---|---|
- **다음 단계로 넘길 것**: 보완 필요 항목과 위험 수준, 제출 전 확인해야 할 쟁점

### 5단계. 사업단장 보고용 1페이지 — 전문가: `report-summarizer`(보고서 요약가)
- **위임**: `report-summarizer` 서브에이전트가 설치되어 있으면 그에게 맡긴다. 없으면 아래 요령으로 직접 한다.
- **요령**:
  - A4 1페이지, 개조식("~함/~임/~요망") 800~1,200자, 최대 1,500자.
  - 결론을 먼저 쓰고 근거는 아래로. 제목만 읽어도 결론이 보이게 쓴다.
  - 주요 내용 항목마다 수치 또는 비교 근거를 1개 이상 넣고, **시사점은 굵게** 표시한다.
  - 권고에는 담당 부서·기한·기대 결과를 반드시 적는다.
  - 자료에 없는 수치는 "[자료 확인 필요]"로 남기고 절대 채워 넣지 않는다.
- **이 단계 산출물**: 1페이지 보고(계획보고) — 1.개요 → 2.주요 내용(발견 3~5개, 시사점 굵게) → 3.영향 및 기대효과 → 4.추진(건의) 사항(긴급/높음/보통 + 담당·기한·기대 결과) → 5.향후 계획 + 결정 요청 사항. 끝에 "붙임: 1. 사업계획서 초안 1부. 2. 세목별 예산표 1부. 끝."을 붙인다.
- **다음 단계로 넘길 것**: 없음(최종 단계)

## 최종 산출물
- 동향 브리프(출처 목록 포함)와 동향 평가표
- 사업계획서 초안(7개 절) + 평가지표 대응표
- 세목별 예산 편성·집행 계획표(산출 근거 포함)
- 규정·법령 준수 검토 보고서
- 사업단장 보고용 1페이지 계획보고
- 파일이 필요하면 계획서는 DOCX(python-docx), 예산표는 XLSX(openpyxl, 합계는 수식)로 만든다. HWP가 필요하면 DOCX를 한컴오피스에서 열어 "다른 이름으로 저장 → HWP"로 변환하도록 안내한다.

## 하지 말 것
- 없는 사실·수치·법령 조항 번호를 지어내지 않는다. (공통)
- 개인정보(이름·학번·연락처)를 예시나 결과에 넣지 않는다. (공통)
- 공고문을 읽지 않은 상태에서 형식 요건(분량·서식·첨부)을 단정하지 않는다. 모르면 "[공고 확인 필요]"로 남긴다.
- 계획서 본문에 없는 활동을 예산에 넣거나, 예산에 없는 인력을 본문에 쓰지 않는다. 글과 숫자는 같은 이야기를 해야 한다.
- 계획서에 명시되지 않은 "국내 최초·대규모" 프로그램을 덧붙이거나 기관 역량을 부풀리지 않는다.
