# 📝 보고 요약

수십 쪽짜리 보고서, 평가 결과, 설문 집계, 외부 컨설팅 자료를 붙여넣으면 결재권자가 3분 안에 읽고 결정할 수 있는 A4 1페이지 개조식 보고로 바꿔 드립니다. 상급자에게 보고를 올려야 하는 행정직원, 사업단 담당자, 부서 실무자를 위한 스킬입니다. 결론을 맨 앞에 두고, 모든 주장에 원자료의 수치를 붙이며, 자료에 없는 것은 채워 넣지 않습니다.

## 시작할 때 물어볼 것
1. 누구에게 올리는 보고인가요? (기본값: 부서장. 총장·처장·사업단장·기관장 등 결재권자에 맞춰 상세 수준을 조절)
2. 보고 종류는 무엇인가요? 검토보고 / 결과보고 / 계획보고 (기본값: 자료 성격을 보고 판단해 제안)
3. 결재용 DOCX 파일이 필요한가요? (기본값: 채팅창 마크다운만)

각 단계가 끝나면 "여기까지 확인하시겠어요, 계속 진행할까요?"를 한 번만 묻고, 사용자가 "계속"이라고 하면 이후 단계는 멈추지 않고 진행합니다.

## 진행 단계

### 1단계. 보고 대상·목적 확인과 자료 분석 — 전문가: `report-summarizer`(보고서 요약가)
- **위임**: `report-summarizer` 서브에이전트가 설치되어 있으면 그에게 맡긴다. 없으면 아래 요령으로 직접 한다.
- **요령**:
  - 자료를 끝까지 읽고, 내용을 SCQA(상황–문제–질문–답) 네 요소에 대응시킨다. "결재권자가 결정해야 할 질문"이 무엇인지 먼저 한 줄로 적는다.
  - 수치화할 수 있는 근거(집행률·달성률·증감률·인원·금액)를 모두 뽑는다. 전년 실적, 유사 사업 평균, 평가 기준선 같은 비교 기준이 있는지 찾는다.
  - 자료의 빈틈과 불확실한 부분을 표시한다. 자료에 없는 수치는 "[자료 확인 필요]"로 남기고 절대 채우지 않는다.
  - 발견 항목을 기관에 미치는 영향이 큰 순서로 정렬한다(피라미드 원칙: 결론 먼저, 근거는 아래로).
- **이 단계 산출물**: 분석 메모(보고 대상·종류, 결정해야 할 질문 1줄, 수치 근거 목록, 자료 빈틈 목록)
- **다음 단계로 넘길 것**: 분석 메모와 영향 순으로 정렬된 발견 3~5개

### 2단계. 1페이지 개조식 요약 작성 — 전문가: `report-summarizer`(보고서 요약가)
- **위임**: `report-summarizer` 서브에이전트가 설치되어 있으면 그에게 맡긴다. 없으면 아래 요령으로 직접 한다.
- **요령**:
  - 분량은 A4 1페이지. 개조식 기준 800~1,200자, 최대 1,500자. 문장은 "~함/~임/~요망"으로 끝낸다.
  - 제목만 읽어도 결론이 보이게 쓴다. "OO사업 현황 보고"보다 "OO사업 집행률 부진에 따른 2학기 집행 계획(안)"이 낫다.
  - 주요 내용 항목마다 수치 또는 비교 근거를 1개 이상 넣고, **각 항목의 시사점은 굵게** 표시한다.
  - 추진(건의) 사항에는 우선순위(긴급/높음/보통)와 담당 부서·기한·기대 결과를 반드시 붙인다.
  - 어조는 단정적, 사실 기반, 결과 지향. 제공된 자료 밖의 가정은 0건.
  - 다 쓴 뒤 점검: 1,500자 이내인가, 모든 발견에 수치가 있는가, 권고에 담당·기한·기대 결과가 있는가, 자료에 없는 수치가 섞였는가.
- **이 단계 산출물**: 아래 결재용 요약 서식

```markdown
# [제목] (검토보고 / 결과보고 / 계획보고 중 택일)

## 1. 개요
- [현황과 배경, 지금 보고하는 이유. 현재와 목표의 격차 포함]

## 2. 주요 내용
- **[발견 1]**: [수치화된 내용]. **시사점: [기관·사업에 미치는 영향]**
- **[발견 2]**: [비교 근거]. **시사점: [전략·계획에 미치는 영향]**
- **[발견 3]**: [측정 결과]. **시사점: [운영에 미치는 영향]**

## 3. 영향 및 기대효과
- **예산·재정**: [금액 또는 비율로 표시한 영향]
- **위험·기회**: [크기를 비율 또는 가능성으로]
- **시점**: [효과 실현 시기: 2026학년도 2학기, 3차년도 연차평가 전 등]

## 4. 추진(건의) 사항
- **[긴급]** [조치] — 담당: [부서] | 기한: [날짜] | 기대 결과: [수치화된 결과]
- **[높음]** [조치] — 담당: [부서] | 기한: [날짜] | 기대 결과: [수치화된 결과]
- **[보통]** [조치] — 담당: [부서] | 기한: [날짜] | 기대 결과: [수치화된 결과]

## 5. 향후 계획
1. **[즉시 조치 1]** — 기한: [30일 이내 날짜]
2. **[즉시 조치 2]** — 기한: [30일 이내 날짜]

**결정 요청 사항**: [결재권자가 결정할 것]을 [기한]까지

붙임: 1. 상세 분석 자료 1부. 끝.
```

- **다음 단계로 넘길 것**: 완성된 요약 마크다운, 붙임으로 안내할 원자료 이름

### 3단계. 결재용 DOCX 만들기(선택) — 전문가: `document-generator`(문서 생성기)
- **위임**: `document-generator` 서브에이전트가 설치되어 있으면 그에게 맡긴다. 없으면 아래 요령으로 직접 한다. 사용자가 파일을 원하지 않으면 건너뛴다.
- **요령**:
  - `python-docx`로 만든다. 설치가 필요하면 `pip install python-docx`를 먼저 알린다.
  - 글꼴·크기는 Normal 스타일에 지정(기본 맑은 고딕 11pt). 제목 위계는 문서 제목 스타일을 써서 접근성을 지킨다.
  - 결재 문서 관행에 맞춰 상단에 결재선("결재: 담당 / 팀장 / 부서장")을 글자로 넣고, 마지막에 "붙임 … 1부. 끝." 표기를 유지한다. 서명·직인은 만들지 않는다.
  - 요약 내용을 데이터로 받아 채우는 함수로 만든다. 사용자가 주지 않은 값은 "[입력 필요]"로 남긴다.
  - 생성 후 파일을 열어 1페이지를 넘지 않는지, 한글이 깨지지 않는지 확인한다. 넘치면 2단계로 돌아가 줄인다.
  - HWP가 필요하면 한컴오피스 한글에서 DOCX를 열어 "다른 이름으로 저장 → HWP/HWPX"로 변환하도록 안내한다.
- **이 단계 산출물**: `요약보고_[제목]_[날짜].docx` + 생성 스크립트 + 수정 방법 안내
- **다음 단계로 넘길 것**: 없음(마무리)

## 최종 산출물
- 1페이지 개조식 요약 마크다운(개요·주요 내용·영향·추진 사항·향후 계획·결정 요청 사항)
- 자료 빈틈 목록("[자료 확인 필요]"로 표시된 항목)
- (선택) 결재선이 들어간 DOCX 파일과 생성 스크립트. HWP는 DOCX를 한컴오피스에서 변환

## 하지 말 것
- 없는 사실·수치·법령 조항 번호를 지어내지 않는다. (공통)
- 개인정보(이름·학번·연락처)를 예시나 결과에 넣지 않는다. (공통)
- 자료에 없는 수치를 그럴듯하게 채우지 않는다. 빈틈은 "[자료 확인 필요]"로 남긴다.
- 1페이지(최대 1,500자)를 넘기지 않는다. 길어지면 상세는 붙임으로 돌린다.
- 결론 없이 배경 설명부터 시작하지 않는다. 첫 줄만 읽어도 결론을 알 수 있어야 한다.
