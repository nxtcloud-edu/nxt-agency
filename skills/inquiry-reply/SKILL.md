# 💬 민원·문의 답변

이메일, 홈페이지 게시판, 국민신문고, 전화 메모로 들어온 문의나 민원을 붙여넣으면 정확한 근거와 정중한 태도를 갖춘 답변 초안을 만들어 드립니다. 학사·행정 문의를 받는 행정직원, 사업단 담당자, 공공기관 민원 담당자를 위한 스킬입니다. 답변 하나에 결론, 근거(규정·지침 이름), 다음에 할 일이 반드시 들어가고, 보내기 전에 규정 근거와 개인정보 노출을 한 번 더 점검합니다.

## 시작할 때 물어볼 것
1. 어떤 경로로 들어온 문의인가요? 이메일 / 게시판 / 국민신문고·민원창구 / 전화·방문 (기본값: 이메일 답변 서식)
2. 답변 근거가 될 규정·지침·공지의 이름이나 내용이 있으면 알려 주세요. (기본값: 근거 자리를 "[규정명 확인 필요]"로 남기고 진행)
3. 문의자는 누구인가요? 본인 / 학부모 등 제3자 / 외부기관 (기본값: 본인. 제3자면 개인정보 안내 방식으로 답변)

각 단계가 끝나면 "여기까지 확인하시겠어요, 계속 진행할까요?"를 한 번만 묻고, 사용자가 "계속"이라고 하면 이후 단계는 멈추지 않고 진행합니다.

## 진행 단계

### 1단계. 문의 분류와 이관 여부 판단 — 전문가: `inquiry-responder`(민원·문의 응대원)
- **위임**: `inquiry-responder` 서브에이전트가 설치되어 있으면 그에게 맡긴다. 없으면 아래 요령으로 직접 한다.
- **요령**:
  - 경로, 문의자 구분(학생·학부모·교수·직원·외부기관·일반), 긴급도(낮음·보통·높음), 감정 상태(평온·불만·격앙)를 파악한다.
  - 성적·학적·장학·상담·급여·계좌처럼 개인정보가 필요한 문의면 본인 확인이 먼저다. 학부모·배우자·지도교수 등 제3자에게는 본인 동의나 법령 근거가 없는 한 "본인이 직접 확인할 수 있는 방법"만 안내한다. 성인 학생의 정보는 부모라도 예외가 아니다.
  - 아래 이관 기준에 해당하면 담당자가 직접 답하지 말고 이관 대상과 사유를 표시한다.
  - 감정이 격한 민원은 경청 → 공감("불편을 드려 죄송합니다", 단 과실을 성급히 인정하지 않음) → 사실 확인 → 대안 제시 → 경계 설정 → 기록 순서로 다룬다.
  - 바로 답할 수 없으면 "언제까지 답하겠다"는 첫 회신을 당일 안에 먼저 보내는 것을 권한다.
- **이 단계 산출물**: 분류표

| 항목 | 내용 |
|---|---|
| 경로 / 문의자 구분 | |
| 문의 요지(개인 식별 정보 최소화) | |
| 긴급도 / 감정 상태 | |
| 본인 확인 필요 여부 | |
| 이관 여부와 대상 | (예: 규정 해석이 갈림 → 부서장 / 폭언·위협 → 부서장·보안 / 언론·감사 관련 → 대외협력·감사 부서 / 개인정보 유출 의심 → 개인정보 보호 담당 / 소송 예고 → 법무) |

- **다음 단계로 넘길 것**: 분류표, 답변에 쓸 근거 자료, 답변 서식 종류(이메일 / 회신 공문 / 게시판 공개 답변)

### 2단계. 답변 초안 작성 — 전문가: `inquiry-responder`(민원·문의 응대원)
- **위임**: `inquiry-responder` 서브에이전트가 설치되어 있으면 그에게 맡긴다. 없으면 아래 요령으로 직접 한다.
- **요령**:
  - 순서는 결론 → 근거(규정·학칙·지침·공지의 이름과 내용) → 해당 조건·예외 → 다음 절차(무엇을·언제까지·어디서·필요 서류).
  - 확실하지 않은 규정은 추측으로 답하지 않고 "확인 후 회신"으로 쓴다. 근거 이름을 모르면 "[규정명 확인 필요]"로 남긴다.
  - "저희 소관이 아닙니다"로 끝내지 않는다. 담당 부서와 연락처를 안내해 연결한다.
  - 반말·훈계·책임 전가 표현을 쓰지 않는다. 문의자가 누구든 같은 기준으로 답한다.
  - 게시판 공개 답변에는 문의자를 식별할 수 있는 정보를 쓰지 않고 상세 내용은 개별 연락으로 돌린다. 단체 회신은 숨은참조.
- **이 단계 산출물**: 이메일 답변 서식(아래) 또는 민원 회신문(공문) 구성

```
제목: [Re] {문의 요지} 문의에 대한 답변 ({부서명})

{호칭}님, 안녕하십니까. {기관·부서명} {담당 직위}입니다.
{날짜} 문의해 주신 {문의 요지}에 대해 답변드립니다.

■ 문의 내용
  - {문의자가 물은 내용을 한두 줄로 확인}

■ 답변
  - {결론을 먼저}
  - {근거: 규정·학칙·지침·공지 명칭과 해당 내용}
  - {해당되는 조건·예외}

■ 다음 절차
  - 하실 일: {무엇을}, 기한: {언제까지}, 방법·장소: {어디서·어떻게}
  - 필요 서류: {목록}

추가로 궁금한 점은 {전화번호}, {이메일}로 연락 주시면 안내해 드리겠습니다.
감사합니다.

{기관·부서명} {직위} {이름} 드림
```

민원 회신문(공문)은 ① 수신·제목("○○ 관련 민원 회신") ② 민원 요지(접수일, 내용 개조식) ③ 검토 결과(관련 규정·사실관계·판단) ④ 조치 사항(또는 어려운 사유와 대안) ⑤ 이의 제기·추가 문의 안내(담당·연락처·불복 절차) ⑥ 첨부 순서로 구성한다.

- **다음 단계로 넘길 것**: 답변 초안 전문, 인용한 규정·지침 이름 목록

### 3단계. 규정 근거와 개인정보 노출 점검 — 전문가: `compliance-checker`(규정·법령 검토관)
- **위임**: `compliance-checker` 서브에이전트가 설치되어 있으면 그에게 맡긴다. 없으면 아래 요령으로 직접 한다.
- **요령**:
  - 이 점검은 법률 자문이 아니다. 조항 번호·과태료·처벌 수위를 확실히 모르면 적지 않고 "개인정보보호법상 확인 필요"처럼 법령명 수준으로만 쓴다.
  - 답변에 인용한 규정·지침 이름이 실제 자료에 있는 것인지, 없는 근거를 만들어 넣지 않았는지 확인한다.
  - 답변 본문·첨부·참조(CC)에 다른 사람의 이름·학번·연락처·사연이 섞이지 않았는지, 본인 확인 없이 개인 정보를 알려주는 문장이 없는지 본다.
  - 판단이 갈리는 사안, 금전·성적·학적 등 권리에 영향이 큰 결정은 "부서장(또는 법무·감사 부서) 확인 필요"로 표시한다.
  - 답변 후 남길 응대 기록(접수·처리·결과·개선) 항목을 함께 정리하고, 반복 문의면 FAQ 추가를 제안한다.
- **이 단계 산출물**: 점검표

| 점검 항목 | 결과 | 조치 |
|---|---|---|
| 인용 규정·지침이 실제 자료에 근거하는가 | ☐ | |
| 개인정보(타인 정보·본인 확인 전 정보) 노출이 없는가 | ☐ | |
| 결론·근거·다음 절차가 모두 있는가 | ☐ | |
| 이관·상급자 확인이 필요한 사안인가 | ☐ | |
| 처리기한(첫 회신 당일, 최종 답변 기관 처리기한) 안내가 있는가 | ☐ | |

- **다음 단계로 넘길 것**: 없음(마무리). 점검에서 걸린 항목은 2단계 초안을 수정한 뒤 최종본을 낸다.

## 최종 산출물
- 보낼 수 있는 상태의 답변 초안(이메일 서식 / 회신 공문 / 게시판 공개 답변 중 하나)
- 분류표(경로·문의자·긴급도·본인 확인·이관 여부)
- 점검표와 "[규정명 확인 필요]", "부서장 확인 필요"로 남긴 항목 목록
- 응대 기록에 남길 요지(접수일·문의 요지·답변 요지·후속 조치)

## 하지 말 것
- 없는 사실·수치·법령 조항 번호를 지어내지 않는다. (공통)
- 개인정보(이름·학번·연락처)를 예시나 결과에 넣지 않는다. (공통)
- 본인 확인 전에, 또는 제3자에게 성적·학적·장학·상담 정보를 알려주는 문장을 쓰지 않는다.
- 확실하지 않은 규정을 추측으로 단정하지 않는다. "확인 후 회신"이 정답이다.
- 과실이나 책임을 성급히 인정하거나, 반대로 "소관이 아니다"로 끝내지 않는다.
