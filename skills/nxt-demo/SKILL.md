# 🎬 샘플로 체험하기

nxt-agency를 처음 쓰는 분을 위한 체험 명령입니다. 자기 자료를 넣지 않아도 됩니다. 이 스킬 폴더의 `samples/` 안에 명령마다 가상 데이터가 들어 있고, 사용자가 고른 샘플로 실제 명령을 끝까지 실행해 "이런 결과가 나온다"를 보여 줍니다. 모든 샘플은 가상 기관(한빛대학교)과 가상 인물의 데이터이며, 실제 자료로 바꿔 쓰는 방법을 마지막에 안내합니다.

## 시작할 때 물어볼 것
1. 어떤 일을 하시는 분인가요? 사업단 / 행정·공공기관 / 교수·연구자 / 학생 (기본값: 묻지 않고 아래 메뉴 전체를 보여 준 뒤 고르게 한다)
2. 체험할 명령을 고르세요. 번호나 이름으로. (기본값: 그 직업군의 첫 번째 명령)

한 번에 하나만 체험합니다. 끝나면 "다른 것도 해 볼까요?"라고 묻습니다.

## 진행 단계

### 1단계. 메뉴 보여 주기
아래 표를 사용자의 직업군에 맞게(모르면 전체) 보여 주고 하나를 고르게 한다. 각 줄은 "명령 · 하는 일 · 샘플 내용" 형식으로 짧게.

| 직업군 | 명령 | 하는 일 | 샘플 |
|---|---|---|---|
| 사업단 | `/business-plan` | 사업계획서 초안 | 가상 공고 요강 + 사업단 현황 |
| 사업단 | `/performance-report` | 성과보고서 | KPI 실적표(미달 지표 포함) + 만족도 |
| 사업단 | `/event-prep` | 행사 준비 | 성과발표회 개요(담당 미정 항목 있음) |
| 사업단 | `/budget-check` | 예산 집행 점검 | 세목별 집행 현황(부진·과집행 섞임) |
| 행정 | `/meeting-minutes` | 회의록 | 운영위원회 녹취록(결정·논의 섞임) |
| 행정 | `/report-summary` | 1페이지 보고 | 중간평가 자체보고서 요약본 |
| 행정 | `/inquiry-reply` | 민원·문의 답변 | 문의 4건(개인정보 함정 포함) |
| 행정 | `/consent-form` | 개인정보 동의서 | 설문 계획(과다 수집 항목 포함) |
| 교수·연구자 | `/literature-review` | 선행연구 정리 | 주제 메모 + 가상 문헌 10편 |
| 교수·연구자 | `/research-proposal` | 연구계획서 | 가상 공고 발췌 + 연구자 프로필 |
| 교수·연구자 | `/syllabus` | 강의계획서 | 과목 개요 + 지난 강의평가 |
| 학생 | `/cover-letter` | 자기소개서 | 공공기관 공고 + 내 경험 목록 |
| 학생 | `/semester-plan` | 학기 계획 | 학생 상황 메모 |
| 학생 | `/capstone` | 캡스톤 프로젝트 | 기능이 너무 많은 아이디어 메모 |

### 2단계. 샘플의 내용을 먼저 설명하기
- 고른 명령의 `samples/<명령 이름>/` 폴더에서 `README.md`와 입력 파일을 읽는다. (이 SKILL.md와 같은 폴더 아래에 있다. 파일을 읽을 수 없는 환경이면 사용자에게 그 폴더의 파일을 붙여 넣어 달라고 한다.)
- **결과물을 이해하려면 입력에 무엇이 있었는지 알아야 한다.** 실행 전에 "자료 소개"를 아래 서식으로 보여 준다. 줄글로 풀지 말고 **불릿 5개**로만 쓴다. README의 **내용** 불릿이 그 재료다.
  ```
  📂 자료 소개 — <파일명> (<줄 수 또는 행 수>)
  무슨 자료: 한 줄 (예: 한빛대 LINC 3.0 사업단 운영위원회 녹취록, 발언자 6명)
  들어 있는 내용 — 불릿 딱 5개, 한 줄씩 (README의 **내용** 불릿을 그대로 써도 된다):
    - 무엇을 다루는 자료인지 (규모·시점)
    - 핵심 항목 1 (안건·열·주제 + 숫자)
    - 핵심 항목 2
    - 핵심 항목 3
    - 정해지지 않았거나 빠져 있는 것
  일부러 넣어 둔 함정: 2~3개 (예: 동의서 담당자가 정해지지 않음 / 학부모가 자녀 성적을 물음)
  ```
- 함정은 "이 부분을 명령이 어떻게 처리하는지 보세요"라고 짚어 준다.
- 원문 전체를 보고 싶어 하면 그대로 보여 준다("원문 보여 줘").
- "시작할까요?" 한 번만 묻는다.

### 3단계. 명령을 그대로 실행하기
- 해당 스킬(`/<명령 이름>`)이 설치되어 있으면 그 스킬의 절차를 따른다. 스킬이 "시작할 때 물어볼 것"에서 묻는 값은 샘플 README의 "이렇게 시작하세요" 문장과 입력 파일에서 채우고, 사용자에게 다시 묻지 않는다.
- 스킬이 없는 환경이면 README의 "기대 결과"에 적힌 산출물을 같은 서식으로 직접 만든다.
- 단계마다 멈추지 않고 끝까지 진행한다. 단, 실제 파일(DOCX 등)을 만드는 단계는 "체험이므로 파일 대신 본문으로 보여 드립니다"라고 하고 건너뛴다.
- 결과를 보여 줄 때는 **함정이 어떻게 처리됐는지**를 결과 바로 아래에 "👀 이렇게 처리했습니다" 2~3줄로 덧붙인다. (예: "동의서 담당은 자료에 없어 '미지정'으로 남겼습니다", "이월·전용은 결정이 아니라 논의라 미결사항으로 뺐습니다") 입력과 출력을 이어서 보게 하는 것이 체험의 목적이다.

### 4단계. 결과 뒤에 "내 자료로 하려면"
결과를 보여 준 뒤 다음 세 줄을 덧붙인다.
1. 실제로 쓸 때 치는 명령: `/<명령 이름> <내 상황 한 줄>` 예시 1개
2. 준비할 자료: 샘플에서 쓴 파일 종류를 내 자료로 바꾸면 된다는 것(예: "녹취록 → 우리 회의 녹취록이나 메모")
3. 주의: 이름·학번·연락처는 지우고 넣기

## 최종 산출물
- 선택한 명령의 실제 산출물(본문으로)
- "내 자료로 하려면" 안내 3줄

## 하지 말 것
- 샘플 데이터가 실제 기관·인물의 것인 양 말하지 않는다. 결과에도 "샘플(가상 데이터)" 표시를 남긴다.
- 샘플에 없는 사실·수치를 지어내 채우지 않는다. 비어 있는 값은 "[확인 필요]"로 둔다.
- 자료 소개 없이 바로 결과를 내지 않는다. 입력을 모르면 결과를 평가할 수 없다.
- 자료 소개를 줄글이나 불릿 6개 이상으로 늘리지 않는다. 5개면 충분하다.
- 여러 명령을 한꺼번에 돌리지 않는다. 하나 끝내고 다음을 묻는다.
- 사용자가 아직 고르지 않았는데 임의로 실행하지 않는다.
